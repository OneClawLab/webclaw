# (问题树)知识库结构说明

## 背景
### 关于Eidux
#### 产品定位：
  帮助(有意愿的)终生学习者在对复杂问题的 `学习/研究/思考/解决` 过程中，高效的组织信息、结构化的思考探索、更快的形成高质量的理解和判断的一个桌面工具应用。
#### 目标用户：
- 变换快速/知识要求多的领域（技术、研究、产品、投资、管理），学习目的以判断、决策和行动为导向。
- 用户认知自省能力高，能识别理解偏差，投入度足够高，但想解决的问题都很复杂，希望借助工具指导整个探索过程。
- 非目标用户：以快速解决日常工作/考试为目的的用户。学习动机不足的用户。

## 是什么
  Eidux支持多个知识库，每个知识库亦即一个问题树，致力于解决一个复杂问题，每个知识库为一个本地目录，文档主要为.md格式。
  Eidux支持文档式AI聊天(聊天会话就是一个由若干连续的Q/A小节组成的.md文档)。

## 知识库结构
### 包含的内容
  一个知识库包含结构化组织的一个复杂问题(即根问题)探索过程中的**所有信息**：输入、过程(Chat)、中间产物、最终输出。
### 文件系统目录结构  
#### 结构
  **目录分为三种:**
    问题目录（包含一个 index.md 文档，可嵌套），目录名为问题的短语描述。
    普通目录(包含任意普通子目录和文件，可嵌套)，目录名为任意
    隐藏会话目录（一个位于问题目录中的 .chats/ 子目录，内部包含的每个.md文件为一个AI聊天会话）。

    根目录就是**根复杂问题的**"问题目录"。

  **文件:**
    .chats 目录内只包含一层平铺的 .md 文档，文件名为 '日期+自动生成的讨论主题短语).md'。
    index.md 文档为'问题目录'内的入口文档，包含当前问题的总览信息，也包含到'问题目录'内的其他子目录(可为问题目录或普通目录)及文档的简要说明和链接。
    其他文件均为当前问题的附属资源(一般均应在 index.md 里提及)。
#### 示例结构
```
{root_problem}/
  .chats/     <- 根问题层级的AI会话记录
  index.md    <- 根问题描述与子文档链接
  a1.md       <- 附属文档
  a2/         <- 普通附属文档目录
    b1.md
    b2.pdf
  S1/         <- 子问题目录
    .chats/   <- 当前子问题层级的AI会话记录
    index.md  <- 子问题描述与文档链接
```

## 如何使用知识库

### 宏观了解一个现有的(但自己不了解的)知识库
1. 从根目录的 index.md 开始，了解根问题的基本信息
2. 从根目录的 index.md 中的 链接，可以了解:
   - 根问题的附属资源(普通子目录/文档)有哪些/是做什么用的。然后可以沿着链接继续下钻了解。
   - 根问题的子问题有哪些/其相互关系如何/子问题和根问题的关系如何等等，然后可以继续下钻研究各子问题目录中的 index.md。
3. 以此类推，可以从上往下的了解整个知识库。

### 日常探索(如何在一个知识库上日常工作，推进其探索)
1. 根据了解到的信息，选定一个(子)问题作为当前Scope。
2. 针对已有的信息，进行探索。探索方式可能包括：
  - 自主思考，然后自行改写现有文档。
  - 和AI一起探讨，然后自行改写现有文档。
  - 和AI一起探讨，让AI用探索结果更新现有文档。
  - 在Eidux之外探索，然后在Eidux里继续做以上探索。
3. 如此往复循环。

### 利用Eidux给出的 What's Next建议
在探索过程中，可以按需选定一个范围: 一个问题 + 一个未来的时间段(如短期中期长期),Eidux可以给出What's Next建议。
